# 设备测试工具

`probe/syscalls.c` 和 `cowtest/` 在 M1 宿主 App（`app.amphora.next`）的沙箱里跑；宿主源码在提交 `4efaf0f` 的 `app/`，现在的 `app/` 没有 `amphora.exec` 钩子。其余的用现在的 App（`app.amphora`）。PE 程序用 Wine 分支的构建镜像编译（`amphora/Dockerfile`，下称 `amphora-wine-build:1`，里面有 llvm-mingw）。

| 工具 | 测什么 | 编译 | 运行 |
|---|---|---|---|
| `probe/syscalls.c` | Wine 要用的系统调用是否被 app 的 seccomp 放行 | NDK clang `--target=aarch64-linux-android30` | 放进 `files/`，`am start -n app.amphora.next/org.winehq.wine.WineActivity --es amphora.exec files/probe-syscalls`，看 `logcat -s amphora-probe`（必须由 App 启动：`run-as` 不带 app 的 seccomp） |
| `fextest/hello.c` | FEX：64 位（ARM64EC）和 32 位（WoW64）x86 能不能跑：CPUID、SSE、线程原子操作、异常恢复，最后弹消息框 | `x86_64-w64-mingw32-clang -O2 -o hello64.exe hello.c -luser32`，`i686-…` 同理出 `hello32.exe` | 放到共享存储，在 App 里作为游戏添加并启动（不需要 M1 宿主）；`-q` 不弹框，`--log <文件>` 把报告也写进文件（`device/smoke.sh` 靠它拿结果） |
| `cowtest/` | 薄前缀写时复制（12 §3.3） | `aarch64-w64-mingw32-clang -O2 -o cowtest.exe cowtest.c` | 把 `cowtest.exe`、`run.sh` 放进 `files/`，`run-as app.amphora.next sh files/run.sh $PWD/files ro` |
| `probe/vkahb.c` | 交换链（12 §3.1）要用的东西在 Wine 那样启动的进程里是否可用：系统 `libvulkan.so` 给出 GPU；自己分配的 AHardwareBuffer 能导入成可渲染的 VkImage（RGBA8 unorm / sRGB、A2B10G10R10、RGBA16F、RGB565，含非对齐尺寸）；渲染完成能导出成 sync fd；sync fd 能导入信号量和 fence。另外列出 32 位映射要用的扩展有没有 | NDK clang `--target=aarch64-linux-android30 -O2 -Wl,-z,max-page-size=16384 -o probe-vkahb vkahb.c -lvulkan -landroid` | `adb push` 到 `/data/local/tmp`，`run-as app.amphora` 下拷进 `cache/`，`/system/bin/linker64 $PWD/cache/probe-vkahb`（和 Wine 一样经系统 linker 启动）。逐项打印，最后 `PASS` / `FAIL` |
| `vktest/` | Wine 里的 Vulkan：不带参数是离屏（真正的图形管线画三角形再回读，逐像素核对），结束时弹消息框；`--window` 是出画（窗口、surface、交换链，转动的三角形，结束时报帧率），可选 `--frames N`、`--mode fifo\|mailbox\|immediate`、`--size WxH` | `./build.sh` 出 `out/vktest-arm64.exe`、`vktest64.exe`、`vktest32.exe`（要 Docker 镜像 `amphora-wine-build:1` 和 Vulkan-Headers，默认取 Homebrew 的）；改了着色器后 `./build.sh shaders` | 放到共享存储，在 App 里作为游戏添加并启动。不要用 `run-as` 无界面跑：win32u 初始化 Vulkan 时会加载显示驱动，没有宿主就卡住 |
| `device/ui.sh` | 从命令行操作设备上的 App：列出屏幕上的文字、按文字点击、截图、解锁、把 `/sdcard/Download/amphora-test/` 下的 exe 加进游戏库、启动游戏、结束会话、改游戏的启动参数（同时可以写别的按游戏设置，如 `display.frameRate=game`）、看最新的会话日志。要测界面本身（添加游戏、设置页、会话菜单）时用它；只是要跑个程序用下面的 `run.sh`，快得多。按界面上的中文文字找控件，界面改了要跟着改 | 不用编译（bash、python3、adb） | `tools/device/ui.sh`（不带参数打印用法）；默认设备是 Y700，`ANDROID_SERIAL` 可改 |
| `device/run.sh` | 不经界面直接开始和结束会话：调试包里有一个只给测试用的入口（`app/src/debug` 的 `RunActivity`，正式包没有），用 SDK 的公开 API 做用户点几下做的事。给一个 exe 路径、启动参数和按游戏设置就开始（不在游戏库里会先加进去；每次都把这个游戏的设置整个换掉，不受上一次影响）。另有几个"等到……为止"的子命令（等日志里出现某行、等结果文件、等会话自己结束）、把游戏从游戏库移除（连同前缀和设置），以及判断截图里有没有 AIO 的方块：先认 Wine 桌面的底色（不是会话的画面直接算失败，比如 App 自己的界面或系统桌面的壁纸），再按清屏色找到 AIO 的窗口，窗口里清屏色以外的部分要占一成以上（D3D 的方块是彩色的，Vulkan 的是灰色带 LunarG 标志，都算）。没有固定的 sleep | 同上 | `tools/device/run.sh start x86/hello64.exe "-q"`；`run.sh end`；`run.sh remove x86/hello64.exe`；不带参数打印用法 |
| `device/smoke.sh` | 设备测试，一行一个结果。不带参数是快的一组，约 20 秒：hello64、hello32（FEX，并且程序退出后会话要跟着结束）、三个架构的 vktest 离屏、64 位 dx11 和 32 位 dx9 各跑 2 秒并看截图里有没有方块。`full` 是 AIO 的 vk、dx8–dx12 × 64 / 32 位全跑，共 17 项约 75 秒。也可以只点名几项。2 秒的帧率不算跑分 | 同上 | `tools/device/smoke.sh`；`tools/device/smoke.sh full`；`tools/device/smoke.sh aio32-dx12 hello32`。退出码是失败的项数 |
| `device/vkrun.sh` | 用给定参数跑一个 vktest，打印它的报告、驱动宿主端的日志（含 Wine 用的是哪个 Vulkan 驱动）和崩溃记录。帧率设置默认是"跟随屏幕"，不管 `--mode` 要什么都每帧显示；要测呈现模式，末尾加 `display.frameRate=game` | 同上 | `tools/device/vkrun.sh x64 "--window --frames 1500 --mode mailbox" "" display.frameRate=game`（第三个参数是截图文件，可以留空） |
| `device/aio.sh` | AIO 图形测试一个后端的跑分（默认 8 秒）：平均 / 最低 / 最高帧率、DXVK 和 vkd3d-proton 的版本、驱动，中途截图并检查方块画出来没有，同时打出当时的 CPU 频率上限。默认带 `display.frameRate=game`（AIO 要的是不限帧）。Y700 在会话期间把 CPU 压在 1996800 / 2246400 kHz，连续测几分钟、机身热了以后第二个值降到 1958400，D3D 的数字跟着低约 20%：只比上限相同的数字，不同就放凉了重跑 | 同上 | `tools/device/aio.sh 64 dx11`；`tools/device/aio.sh 32 dx9 8 display.frameRate=60`。exe 是 `amphora-dev` fork 的构建（`dist/` 里 64 位和 32 位各一个），放在 `/sdcard/Download/amphora-test/aio/` |
